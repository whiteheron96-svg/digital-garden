# VM, 가상환경(.venv), 맥미니… 도대체 뭐가 다른 걸까?

개발을 시작하면 가장 먼저 마주치는 단어들이 있다.

**Ubuntu**, **가상머신(VM)**, **Python 가상환경(.venv)**, **Docker**, **맥미니**.

처음에는 모두 비슷해 보인다.

'가상환경도 만들고 Ubuntu도 설치했는데, 맥미니는 왜 또 사는 거지?'

나 역시 같은 의문을 가졌다.

하지만 하나씩 공부해보니 이들은 서로 경쟁하는 기술이 아니라 **각자의 역할이 완전히 다른 도구**였다.

오늘은 이 차이를 한 번에 정리해보려고 한다.

---

# 1. 운영체제(Ubuntu)는 집이다

가장 먼저 이해해야 하는 것은 Ubuntu다.

많은 사람들이 Ubuntu를 하나의 프로그램이라고 생각하지만, 사실은 Windows나 macOS와 같은 **운영체제(OS)** 이다.

즉,

```
Windows
macOS
Ubuntu
```

는 모두 같은 위치에 있는 존재다.

Ubuntu를 설치한다는 것은 새로운 프로그램을 설치하는 것이 아니라 **새로운 컴퓨터 환경을 만드는 것**에 가깝다.

---

# 2. 가상머신(VM)은 컴퓨터 안의 또 다른 컴퓨터

가상머신은 현재 사용 중인 컴퓨터 안에 새로운 컴퓨터를 만드는 기술이다.

예를 들어 macOS를 사용하는 경우에는 다음과 같은 구조가 된다.

```
MacBook

├── macOS

└── Ubuntu (Virtual Machine)
```

Ubuntu는 실제 컴퓨터처럼 동작한다.

Python도 설치할 수 있고,

MongoDB도 설치할 수 있고,

웹 서버도 실행할 수 있다.

다만 이것은 **Mac의 CPU와 RAM을 함께 사용하는 또 하나의 컴퓨터**일 뿐이다.

VM은 실제 서버와 동일한 환경을 미리 테스트할 때 매우 유용하다.

---

# 3. Python 가상환경(.venv)은 프로젝트 전용 작업실이다

많은 사람들이 VM과 가장 많이 헷갈리는 것이 바로 Python의 가상환경이다.

하지만 둘은 전혀 다른 개념이다.

가상환경은 운영체제를 만드는 것이 아니라 **프로젝트마다 Python 라이브러리를 분리하는 기능**이다.

예를 들어

프로젝트 A는

```
numpy 1.x
pandas 2.x
```

를 사용하고,

프로젝트 B는

```
numpy 2.x
```

를 사용해야 할 수도 있다.

이때 하나의 Python 환경만 사용하면 서로 충돌하게 된다.

그래서 프로젝트마다

```
Economic-AI/

    .venv/
```

를 만들어

각 프로젝트가 독립된 라이브러리를 사용하도록 한다.

즉,

VM은 컴퓨터를 하나 더 만드는 것이고,

`.venv`는 프로젝트마다 전용 작업실을 만드는 것이다.

---

# 4. Docker는 복사 가능한 개발환경이다

VM보다 조금 더 발전한 개념이 Docker이다.

Docker는

```
Ubuntu

Python

MongoDB

FastAPI

Streamlit
```

까지 모두 하나의 이미지로 포장한다.

그러면

Mac에서도

Windows에서도

Ubuntu 서버에서도

동일한 환경으로 실행할 수 있다.

"내 컴퓨터에서는 되는데 서버에서는 안 된다."

라는 문제를 해결하기 위해 Docker가 많이 사용된다.

---

# 5. 맥미니는 왜 따로 살까?

여기서 많은 사람들이 가장 궁금해하는 질문이 나온다.

"Ubuntu VM을 설치하면 되는데 왜 맥미니를 따로 사지?"

답은 의외로 간단하다.

**맥미니는 서버 역할을 하기 때문이다.**

예를 들어 경제 AI 연구 시스템을 만든다고 가정해 보자.

매일 새벽

- 경제 뉴스 수집
    
- MongoDB 저장
    
- 임베딩 생성
    
- RAG 업데이트
    
- AI 요약
    
- Obsidian 저장
    

이 모든 작업은 24시간 실행되어야 한다.

노트북은 항상 켜 둘 수 없다.

하지만 맥미니는

```
24시간 ON
```

상태로 둘 수 있다.

특히 최근에는 Ollama를 이용해 Llama, Qwen 같은 로컬 LLM을 실행하는 용도로 많이 사용된다.

즉,

맥미니는 단순히 작은 컴퓨터가 아니라

**항상 켜져 있는 개인 AI 서버**가 되는 것이다.

---

# 6. GPT를 사용할 때는 맥미니가 필요할까?

반드시 그렇지는 않다.

현재 우리가 사용하는 GPT는

```
내 컴퓨터

↓

인터넷

↓

OpenAI 서버
```

에서 실행된다.

즉, GPT는 내 컴퓨터에서 돌아가는 것이 아니다.

그래서 GPT API를 사용하는 초기 단계에서는

맥미니 없이도 충분하다.

반대로

Llama

Qwen

DeepSeek

같은 오픈소스 LLM을 내 컴퓨터에서 직접 실행하고 싶다면

맥미니가 매우 좋은 선택이 된다.

---

# 7. 내가 선택한 방식

현재 내가 만들고 있는 것은 단순한 뉴스 수집기가 아니라

**경제 AI 연구 시스템(Economic AI OS)** 이다.

처음에는 다음과 같은 구조로 개발하려고 한다.

```
MacBook

↓

Python (.venv)

↓

MongoDB Atlas

↓

OpenAI API

↓

Obsidian

↓

GitHub
```

여기서 중요한 것은 **개발환경까지 코드로 관리하는 것**이다.

프로젝트에는

```
requirements.txt
setup.sh
.env.example
```

를 함께 관리하고,

새로운 컴퓨터에서는

```
git clone

↓

./setup.sh
```

만 실행하면 동일한 개발환경이 자동으로 만들어지도록 설계할 계획이다.

즉, 더 이상 "내 맥북"이 중요한 것이 아니라 **프로젝트 자체가 언제든 복원 가능한 상태**가 되는 것이다.

---

# 마무리

처음에는 VM, 가상환경, Docker, 맥미니가 모두 비슷해 보였다.

하지만 공부를 하면서 이들이 서로 다른 문제를 해결하는 도구라는 것을 알게 되었다.

- **Ubuntu**는 운영체제
    
- **VM**은 컴퓨터 안의 또 다른 컴퓨터
    
- **Python 가상환경(.venv)**은 프로젝트별 라이브러리 관리
    
- **Docker**는 어디서든 동일하게 실행되는 개발환경
    
- **맥미니**는 24시간 동작하는 개인 AI 서버
    

그리고 내가 만들고 싶은 시스템은 결국 이 모든 기술이 하나로 연결된 **나만의 경제 AI 연구원**이다.

앞으로 이 블로그에서는 그 과정을 하나씩 기록해 볼 생각이다.
