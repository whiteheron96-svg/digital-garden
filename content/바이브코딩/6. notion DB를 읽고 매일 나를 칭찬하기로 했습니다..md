# Notion 기록을 읽고 매일 아침 Telegram으로 나를 칭찬해주는 봇 만들기

매일 새벽 6시, 내가 Notion에 남긴 기록을 읽고 Telegram 개인 톡으로 칭찬 메시지를 보내주는 자동화를 만들었다. 처음 목표는 단순했다. 특정 Notion DB에 있는 파일이나 기록을 읽어서 하루에 한 번 나를 칭찬해주는 메시지를 받고 싶었다.

만들다 보니 구조는 조금 더 실용적으로 바뀌었다. 특정 DB 하나만 보는 방식이 아니라, Notion integration이 접근할 수 있는 전체 페이지를 검색하고, 그 기록을 Gemini가 읽어 자연스러운 칭찬 메시지로 바꿔 Telegram으로 보내는 흐름이 되었다.

## 최종 구조

전체 흐름은 이렇다.

```text
GitHub Actions
  -> Notion Search API로 최근 기록 조회
  -> 페이지 제목과 본문 일부 수집
  -> Gemini API로 칭찬 메시지 생성
  -> Telegram Bot API로 개인 톡 발송
```

GitHub Actions는 매일 한국시간 오전 6시에 실행된다. GitHub Actions의 cron은 UTC 기준이기 때문에 실제 설정은 전날 21:00 UTC다.

```yaml
cron: "0 21 * * *"
```

## 왜 특정 DB 대신 전체 Notion 검색으로 바꿨나

처음에는 `NOTION_PRAISE_DATA_SOURCE_ID`를 받아 특정 DB만 읽는 방식으로 생각했다. 하지만 실제로 원하는 것은 특정 DB 하나가 아니라, Notion 전체에 흩어진 기록에서 오늘 칭찬할 만한 흔적을 찾는 것이었다.

그래서 기본 동작을 Notion Search API 기반으로 바꿨다.

```text
NOTION_PRAISE_DATA_SOURCE_ID가 있으면 특정 DB 조회
없으면 Notion Search API로 공유된 전체 페이지 검색
```

단, 여기서 말하는 “전체 Notion”에는 중요한 제한이 있다. Notion API는 내 계정의 모든 비공개 페이지를 자동으로 읽을 수 없다. Integration에 공유된 페이지와 DB만 읽을 수 있다.

따라서 실제로는 칭찬 재료로 쓰고 싶은 상위 페이지나 주요 DB에 Notion integration을 `Connections`로 추가해야 한다. 상위 페이지를 연결하면 그 아래 페이지들이 검색 대상이 된다.

## Secret을 분리한 이유

이미 주식 퀴즈 봇에서 Notion API key와 Telegram bot token을 쓰고 있었다. 하지만 이번 칭찬 봇은 접근해야 하는 Notion DB와 발송 대상이 달랐다.

그래서 기존 secret을 그대로 재사용하지 않고, 칭찬 봇 전용 secret 이름을 만들었다.

```text
NOTION_PRAISE_API_KEY
TELEGRAM_PRAISE_BOT_TOKEN
TELEGRAM_PRAISE_CHAT_ID
```

Gemini API key는 기존 repo secret에 이미 저장되어 있어서 그대로 재사용했다.

```text
GEMINI_API_KEY
```

최종적으로 GitHub Actions에 필요한 secret은 다음 네 개다.

```text
NOTION_PRAISE_API_KEY
GEMINI_API_KEY
TELEGRAM_PRAISE_BOT_TOKEN
TELEGRAM_PRAISE_CHAT_ID
```

## Notion API key 받기

Notion API key는 Notion integration을 만들면 받을 수 있다.

1. `https://www.notion.so/my-integrations` 접속
2. `New integration` 클릭
3. 워크스페이스 선택
4. integration 생성
5. `Internal Integration Secret` 복사

최근 Notion integration key는 `ntn_...` 형태로 시작할 수 있다. 예전 예시에는 `secret_...` 형태가 많지만, `ntn_...`도 정상적인 Notion API key다.

GitHub에는 아래 이름으로 저장했다.

```text
Name: NOTION_PRAISE_API_KEY
Secret: ntn_...
```

그리고 Notion에서 읽고 싶은 상위 페이지나 DB에 이 integration을 연결해야 한다.

```text
Notion 페이지 열기
  -> 우측 상단 ...
  -> Connections
  -> 만든 integration 추가
```

## Telegram 개인 봇 만들기

기존 주식 퀴즈 봇은 그룹 채팅으로 메시지를 보내고 있었다. 칭찬 메시지는 개인 톡으로 따로 받고 싶었기 때문에 Telegram bot도 분리했다.

1. Telegram에서 `@BotFather` 검색
2. `/newbot` 입력
3. 봇 이름 입력
4. 봇 username 입력

봇 username은 반드시 `bot`으로 끝나야 한다. 예를 들어 다음과 같은 형태다.

```text
ellie_praise_bot
```

BotFather가 발급한 token은 GitHub secret에 저장한다.

```text
Name: TELEGRAM_PRAISE_BOT_TOKEN
Secret: 1234567890:AA...
```

중요한 점은 token을 채팅이나 문서에 노출하면 바로 재발급하는 것이 좋다는 것이다. Telegram bot token은 사실상 그 봇을 조작할 수 있는 비밀번호다.

## Telegram chat id 찾기

Telegram Bot API에서 `chat.id`를 찾으려면 봇 username이 아니라 bot token을 써야 한다.

잘못된 예:

```text
https://api.telegram.org/bot<봇 토큰 이름>/getUpdates
```

올바른 예:

```text
https://api.telegram.org/bot1234567890:AA.../getUpdates
```

절차는 다음과 같다.

1. Telegram에서 새 봇에게 개인 메시지로 `hi` 보내기
2. 브라우저에서 `getUpdates` 호출
3. 응답 JSON에서 `chat.id` 확인

응답이 이렇게 비어 있다면:

```json
{"ok": true, "result": []}
```

대부분 봇에게 아직 새 메시지를 보내지 않았거나, `Start`를 누르지 않았거나, 토큰이 다른 봇의 토큰인 경우다.

정상 응답에는 이런 값이 들어 있다.

```json
{
  "message": {
    "chat": {
      "id": 123456789
    }
  }
}
```

이 숫자를 GitHub secret에 저장한다.

```text
Name: TELEGRAM_PRAISE_CHAT_ID
Secret: 123456789
```

## 처음 만든 메시지의 문제

처음에는 Notion에서 찾은 페이지 제목과 본문 일부를 그대로 나열하는 방식이었다.

예시는 이런 식이었다.

```text
2026-06-14 오늘의 칭찬

Notion에 남겨둔 기록을 보니 오늘도 일을 흘려보내지 않고 붙잡아 정리해냈어요.

특히 이 부분이 좋았어요:
- 2025 (내용: 바로가기 / 2023년 회고 / 2025년 회고 / 2022년 회고)
- DAILY STANDUP (...)
- 채널링 (내용: the component gallery : UI 디자인 컴포넌트를 실제 사례와 함께 정리)

작은 항목을 기록하고 다음 행동으로 이어가는 힘이 꽤 단단합니다.
```

동작은 했지만 문제도 분명했다.

- 상위 인덱스 페이지가 섞였다.
- 템플릿 안내문이 칭찬 재료로 들어왔다.
- `채널링`, `채널링 (1)`처럼 비슷한 페이지가 중복으로 들어왔다.
- 칭찬이 너무 일반적이었다.

그래서 1차로 중복 제거와 템플릿 안내문 필터를 넣었다.

```text
이 페이지를 생성한 이후
날짜 필터를
과거 데이터를 원활히
```

이런 문구가 들어간 항목은 칭찬 재료에서 제외했다.

## 왜 Gemini를 붙였나

규칙 기반으로도 어느 정도 개선할 수는 있었다. 예를 들어 제목이나 본문에 `회고`, `디자인`, `컴포넌트`, `업무` 같은 키워드가 있으면 그에 맞는 칭찬 문장을 만드는 방식이다.

하지만 실제로 원하는 것은 단순 분류가 아니라 “내 기록을 읽고 이해한 듯한 칭찬”이었다.

그래서 Gemini API를 연결했다.

Gemini에는 Notion에서 가져온 페이지 제목, 본문 일부, 속성 정보를 넘긴다. 그리고 다음과 같은 요구사항을 줬다.

```text
- 원문에 없는 사실, 성과, 감정 상태를 지어내지 말 것
- 단순히 항목을 나열하지 말 것
- 기록에서 관찰되는 좋은 행동을 구체적으로 칭찬할 것
- 과장하거나 오글거리는 표현은 피할 것
- 담백하고 다정한 톤으로 쓸 것
- 700자 이내로 쓸 것
```

Gemini 모델은 기존 자동화에서 쓰던 것과 맞춰 `gemini-2.5-flash-lite`를 사용했다.

```text
GEMINI_MODEL=gemini-2.5-flash-lite
```

Gemini 호출이 실패해도 Telegram 발송 전체가 실패하지 않도록 fallback도 넣었다. Gemini가 실패하면 규칙 기반 칭찬 메시지를 대신 보낸다.

## GitHub Actions 워크플로

칭찬 봇 워크플로는 `daily-praise-telegram.yml`로 만들었다.

```yaml
name: Daily Praise Telegram

on:
  schedule:
    - cron: "0 21 * * *"
  workflow_dispatch:
    inputs:
      dry_run:
        description: "Print the message without sending it"
        required: true
        default: false
        type: boolean

jobs:
  send-praise:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    env:
      NOTION_API_KEY: ${{ secrets.NOTION_PRAISE_API_KEY }}
      GEMINI_API_KEY: ${{ secrets.GEMINI_API_KEY }}
      TELEGRAM_BOT_TOKEN: ${{ secrets.TELEGRAM_PRAISE_BOT_TOKEN }}
      TELEGRAM_CHAT_ID: ${{ secrets.TELEGRAM_PRAISE_CHAT_ID }}
      NOTION_VERSION: "2026-03-11"
      GEMINI_MODEL: "gemini-2.5-flash-lite"
      PRAISE_TIMEZONE: "Asia/Seoul"
      PRAISE_PERSON_NAME: "이름"
      PRAISE_PAGE_SIZE: "5"
      PRAISE_SEARCH_QUERY: ""
      PRAISE_USE_GEMINI: "1"
      PRAISE_INCLUDE_PAGE_CONTENT: "1"
      PRAISE_CONTENT_BLOCKS: "8"
```

`workflow_dispatch`를 넣어두면 GitHub Actions 탭에서 수동 실행할 수 있다. `dry_run=true`로 실행하면 Telegram 발송 없이 로그에서 메시지만 확인할 수 있다.

## 배운 점

이번 자동화에서 가장 중요한 포인트는 API 연결 자체보다 “접근 범위와 secret 분리”였다.

Notion은 integration에 공유된 페이지만 읽을 수 있다. 따라서 전체 Notion을 읽고 싶다면, 실제로는 읽고 싶은 상위 페이지나 주요 DB들을 integration에 연결해야 한다.

또한 기존 주식 퀴즈 봇과 이번 칭찬 봇은 목적과 대상이 다르다. 그래서 Notion key와 Telegram bot token을 분리했다. 이렇게 해두면 한쪽 자동화를 고쳐도 다른 쪽에 영향이 적고, 나중에 권한을 회수하기도 쉽다.

마지막으로, 처음부터 AI를 붙이는 것보다 먼저 규칙 기반 fallback을 만들어둔 것이 좋았다. Gemini가 실패해도 매일 아침 메시지가 아예 끊기지는 않기 때문이다.

## 다음 개선 아이디어

앞으로 개선한다면 세 가지가 좋아 보인다.

1. 칭찬 재료로 삼을 페이지를 더 잘 고르기
2. 최근 수정 페이지가 아니라 “오늘 작성한 기록”을 우선하기
3. 전날과 비슷한 칭찬이 반복되지 않도록 발송 이력을 남기기

지금 버전은 일단 매일 아침 나의 Notion 기록을 읽고, 그 안에서 구체적인 칭찬거리를 찾아 Telegram 개인 톡으로 보내주는 정도까지 완성했다. 작은 자동화지만, 매일 아침 내가 남긴 기록을 다시 다정하게 돌려받는 장치가 되었다.
