## 만들고 싶었던 것

엑셀로 관리하던 채과(품질조사) 결과를 담당자가 기간별로 선택해 확인하고, 농가에 문자로 보낼 수 있는 Windows 프로그램이 필요했다.

처음부터 복잡한 자동 발송 시스템을 만들기보다, 담당자가 결과를 검토한 뒤 버튼을 눌러 보내는 수동 발송 방식으로 시작했다. 정기 작업 스케줄러 없이도 운영할 수 있고, 잘못된 발송을 줄일 수 있기 때문이다.

## 핵심 요구사항

- 농가 또는 필지별로 나뉜 엑셀 시트에서 조사일과 측정값을 읽기
- 조회 기간을 직접 지정해 해당 기간의 조사 결과를 발송
- 한 달에 여러 번 조사한 결과도 각각 발송
- 이전에 성공적으로 보낸 결과는 신규 발송 목록에서 제외
- 농가와 기간을 지정해 과거 발송 건을 재발송
- 농가 연락처는 조사 파일과 분리된 별도 엑셀에서 관리
- 하나의 농가가 여러 필지를 가질 경우, 필지별 시트를 사용하고 같은 연락처를 연결
- Windows에서 파이썬을 모르는 동료도 실행 가능하게 배포

## 데이터 구조를 단순하게 정한 방법

조사 데이터는 ‘사람 또는 필지마다 하나의 시트’이고, 표가 오른쪽 방향으로 월별로 이어지는 형태였다. 프로그램은 시트 안에서 날짜가 있는 조사 표를 찾아 각 조사 결과를 하나의 발송 대상으로 만들도록 구성했다.

연락처 파일은 조사 파일과 분리했다. 기본적으로 농가명을 연결 기준으로 쓰되, 같은 농가의 여러 필지를 더 안전하게 구분하려면 `시트명` 또는 `필지명` 열을 추가할 수 있도록 했다. 같은 수신 연락처를 여러 필지에 연결하는 것도 가능하다.

## 발송 기준

‘이번 달 결과’처럼 현재 날짜만 기준으로 하면, 전월 말 조사 결과가 다음 달에 확인되는 경우를 놓칠 수 있다. 그래서 월 선택 대신 시작일과 종료일을 직접 지정하는 방식으로 만들었다.

이 방식이면 다음 상황을 모두 처리할 수 있다.

- 12월 말 조사 결과를 1월에 발송
- 1월에 두 번 조사한 결과를 두 건 모두 발송
- 특정 기간의 누락 건만 골라 발송
- 특정 농가와 기간을 선택해 재발송

## 발송 이력으로 중복을 막은 방법

발송 이력은 프로그램 내부의 로컬 데이터베이스에 기록한다. 각 결과는 조사일과 순번 등을 이용해 구분하고, 성공 발송 이력이 있는 결과는 신규 발송 목록에서 제외한다.

재발송은 별도 화면으로 분리했다. 담당자가 농가와 기간을 선택한 뒤 과거 성공 발송 결과만 조회하고, 필요한 행만 다시 보낼 수 있다. 발송 전에는 항상 확인 창을 띄워 실제 문자 발송 여부를 다시 묻도록 했다.

## 화면 설계

첫 화면에서는 두 가지 작업만 선택하게 했다.

1. 신규 결과 발송
2. 발송 이력 · 재발송

브랜드 프로필 이미지에서 색감과 분위기를 가져와 따뜻한 갈색, 오렌지, 크림색 중심의 화면으로 구성했다. 결과 화면에서는 왼쪽에 발송 대상 목록, 오른쪽에 문자 미리보기를 배치했다.

실사용 테스트에서 창 높이에 따라 하단의 발송 버튼이 보이지 않는 문제가 있었다. 그래서 `전체 선택`, `선택 해제`, `선택한 문자 발송` 버튼을 화면 하단에 고정해 작은 화면에서도 항상 보이도록 수정했다.

## 문자 발송 연동

문자 발송은 알리고 API를 사용하도록 구현했다. API 키와 발신번호 같은 민감한 값은 코드나 배포 파일에 넣지 않고, 프로그램의 API 설정 화면에서 각 사용자가 입력해 저장하도록 했다.

문자 내용에는 조사일과 주요 측정값, 기준 범위를 함께 보여 주도록 구성했다. 필지 정보가 있는 경우에는 문자에 필지명도 표시할 수 있다.

## Windows 배포 방식

파이썬 프로그램을 동료가 쉽게 실행할 수 있도록 PyInstaller로 Windows 실행 파일(`.exe`)을 만들었다.

배포 준비 폴더에는 다음을 넣었다.

- 파이썬 소스코드
- 필요한 라이브러리 목록
- 디자인 이미지
- 사용자 안내 PDF
- Windows 빌드 자동화 파일(`build_windows.bat`)

`build_windows.bat`은 Windows 명령을 순서대로 실행하는 파일이다. 한 번 실행하면 필요한 패키지를 설치하고 `.exe`를 만들고, 실행 파일과 안내서를 배포용 ZIP으로 묶는다.

최종적으로 동료에게 전달할 것은 아래 두 파일, 또는 이를 묶은 ZIP 하나다.

- `윈터프린스_문자발송.exe`
- `user-guide.pdf`

## Windows에서 겪은 배포 이슈와 해결

### 1. 배치 파일이 명령을 이상하게 인식함

macOS에서 만든 배치 파일은 줄바꿈 형식이 Windows와 달라, Windows 명령 프롬프트에서 한 줄씩 정상 실행되지 않는 문제가 있었다. 배치 파일을 Windows용 CRLF 줄바꿈으로 바꾸고, 배치 내부 명령과 파일명은 가능한 한 영문으로 단순화했다.

### 2. 클라우드 동기화 폴더가 Python 파일을 점유함

OneDrive나 Dropbox 폴더에서 빌드할 때 동기화 프로그램이 설치 파일을 잠시 사용해 패키지 설치가 실패할 수 있었다. 가상환경은 사용자 로컬 앱 데이터 폴더에 만들도록 바꿔 동기화 폴더의 파일 잠금 영향을 줄였다.

### 3. 한글 파일명 디자인 자산을 찾지 못함

압축을 푼 Windows 환경에서 한글 파일명이 깨지거나 찾지 못하는 문제가 있었다. 배포에 포함하는 이미지와 PDF는 영문 파일명으로 고정해 운영체제와 압축 프로그램 차이를 줄였다.

## 다음 단계

- 발송 전 엑셀 데이터 검증 규칙 강화
- 문자 템플릿을 화면에서 선택하거나 수정하는 기능
- 발송 결과를 엑셀로 내려받는 기능
- 조사 파일 형식이 바뀔 때를 대비한 데이터 검증 화면

## 느낀 점

이번 작업의 핵심은 거대한 시스템을 만드는 것이 아니라, 이미 현장에서 쓰는 엑셀 흐름을 최대한 유지하면서 ‘확인하고 버튼을 눌러 보낸다’는 작은 업무 흐름을 안정적으로 만드는 일이었다.

바이브코딩으로 빠르게 화면과 기능을 만들 수 있었지만, 실제 사용 단계에서는 데이터 형식, 중복 발송, 작은 화면, Windows 줄바꿈, 클라우드 동기화 같은 운영 이슈를 하나씩 확인하는 과정이 더 중요했다. 결국 좋은 자동화는 기술 자체보다 담당자가 믿고 사용할 수 있는 흐름을 만드는 데서 완성된다고 느꼈다.
